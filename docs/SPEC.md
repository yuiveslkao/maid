# maid 仕様書

PC 上でいつでも文字と声で話せる、好みの声と性格のキャラクター兼調べものエージェント。完全に個人用。

## 1. 環境

| 項目 | 内容 |
|---|---|
| CPU | Core i7-11700F（8 コア 16 スレッド） |
| GPU | RTX 3060 Ti（**VRAM 8GB**） |
| RAM | 16GB |
| OS | Windows |
| 音声出力 | ヘッドホン（画面でエコーの除去もかける） |

VRAM 8GB がいちばんの制約です。**GPU は頭脳（LLM）専用**にして、音声認識と音声合成は CPU で動かします。

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| 形 | 自作の Windows アプリ maid.exe（C# / .NET 8・WinForms ＋ WebView2）。クリックで起動。見た目（3D）は持たず、会話のウィンドウだけ |
| PC を汚さない | インストーラー・winget・PATH の変更なし。全部 maid フォルダの `runtime\` に入れる（ネイティブの DLL も %TEMP% に展開せず `lib\` に置く） |
| 入力 | 文字・声・画像（画面のスクショ 1 枚・貼った画像） |
| 待受 | マイクがオンなら常時待受・ウェイクワードなし。会話の画面の「マイク」で切れる |
| Discord | 通話中は自動で声を聞かず、キャラからも話しかけない（文字は使える） |
| 割り込み | キャラが話している途中で話しかけたら止まる |
| 応答速度 | 速いほど良い。目標は話し終わってから 1 秒未満 |
| 頭脳 | ローカル LLM。llama.cpp の llama-server を直接起動。Gemma 4 E4B（unsloth の GGUF Q4_K_M ＋ 画像用の mmproj） |
| 耳 | ReazonSpeech（日本語専用、sherpa-onnx, CPU） |
| 声 | AivisSpeech（コハク/あまあま）。将来は好きな声に近い声を学習したモデル |
| 検索 | 閲覧と検索だけ（ログイン・購入・フォーム送信はしない）。ブラウザは使わない |
| 回答の出し方 | 調べた結果は短く答え、返事の下に出典のリンクを付ける（読み上げない） |
| 外に出してよいもの | **検索語と閲覧したページだけ** |
| 記憶 | 自分の PC に保存。相手のプロフィール（抽象的）と今のこと（具体的・期限付き）と前の会話の要約。キャラの性格は固定で、育てない |
| 話しかける | 会話が 15 分無く、PC を使っているときにキャラから話しかける |
| 見た目 | アイコン（自分でえらぶ画像）だけ。3D はやめた（下の「やめたこと」） |
| 画面共有 | 常に共有するのではなく、頼んだときに画面を 1 枚撮って見せる |

## 3. 全体構成

```
キーボード・貼った画像・画面のスクショ ─┐
マイク（画面で雑音・エコー除去）─▶ 話し終わりの判定 ─▶ 音声認識 ─┴─▶ maid.exe ─┬▶ 頭脳: llama-server（GPU）
                              （Silero VAD）     （ReazonSpeech, CPU）        ├▶ 記憶: data\ ＋ llama-server（bge-m3, CPU）
                                                                              ├▶ Web 検索 ── 外に出る: 検索語・ページの取得
                                                                              └▶ 声: AivisSpeech Engine ─▶ ヘッドホン
```

裏の部品（llama-server 2 つ・AivisSpeech Engine）は maid.exe が起動し、Windows の Job Object に入れる。maid.exe が終われば（落ちても）一緒に止まる。

| 部品 | ファイル | 役目 |
|---|---|---|
| ウィンドウ | `src/Maid/MainForm.cs`・`src/Maid/ui/` | セットアップ → 起動の画面 → 会話を 1 つのウィンドウで切り替える。画面は exe に埋め込み、`https://maid.local/` として出す |
| 会話 | `src/Maid/Conversation.cs`・`src/Maid.Core/ChatSession.cs` | 部品の起動、頭脳への話しかけ、返事を文ごとに声にする、割り込み、キャラから話しかける、記憶のまとめ |
| 頭脳への話しかけ | `src/Maid.Core/Brain.cs`・`Llm.cs` | 今の日時・覚えていること・検索結果を足す。返事の繰り返し（無限ループ）を打ち切る。考えるモードは切る |
| 記憶 | `src/Maid.Core/Memory.cs` | 会話ログ・前の会話の要約・メモ |
| Web 検索 | `src/Maid.Core/WebSearch.cs` | DuckDuckGo（だめなら Mojeek）で検索し、上位ページの本文を抜き出す（SmartReader。PDF は PdfPig） |
| 声 | `src/Maid.Core/Voice.cs` | AivisSpeech Engine に文を渡して wav にする。文ごとに区切って順に読む |
| 耳 | `src/Maid.Core/Listen.cs`・`ui/chat.html` | 画面（WebView2）がマイクを開き、雑音・エコーの除去と音量の自動調整をかけた 16kHz の音を渡す。Silero VAD で区切って ReazonSpeech（sherpa-onnx）で文字にする。Discord 通話中は聞かない |
| 目 | `src/Maid/Screen.cs` | 画面を 1 枚撮る（撮る間だけ自分のウィンドウを隠す）・画像を頭脳に見せる大きさにする |
| セットアップ | `src/Maid/Setup.cs` | 足りないものだけを GitHub・Hugging Face からダウンロード（続きから再開できる）。前の版の Ollama のモデルは引き継ぐ |

### 頭脳（llama-server）の動かし方

RAM を減らすため、GPU に送ったモデルは RAM に残さない。

| オプション | 理由 |
|---|---|
| `-ngl 999` | モデルを全部 GPU に載せる |
| `--load-mode none` | GPU に送り終えたモデルを RAM に残さない（mmap だと Windows 版は 3GB ほど残したままになる） |
| `--lazy-mode on` | Gemma の単語ごとの大きな表（Per-Layer Embeddings）は、要る行だけディスクから読む |
| `--cache-ram 0` | 会話の一時保存をメモリに取らない |
| `--no-repack --no-host` | CPU 用の並べ替えと、GPU とやりとりする固定メモリを使わない（専有メモリにコピーさせない） |
| `--swa-full --ctx-checkpoints 0` | 前の会話を毎回最初から読み直さない（返事が 1 秒ほど早くなる。GPU のメモリを少し多く使う）。途中経過の保存もやめる |
| `-c 8192 -np 1 -fa on -ctk q8_0 -ctv q8_0` | 一度に読める長さを決め、同時の会話は 1 つにし、作業用のメモリを小さくする |
| `--reasoning-budget 0` | 考えてから答えるモードを切る（数秒の無言をなくす） |
| `--mmproj` | 画像を読む部分 |

古い llama.cpp で新しいオプションが使えずにすぐ止まったときは、メモリを節約するオプションを外して起動し直す。

## 4. 応答速度

話し終わってから声が出るまでの内訳（概算）:

| 段階 | 目安 | 調整方法 |
|---|---|---|
| 話し終わり判定 | 約 0.9 秒 | `maid.settings.json` の `silence_ms`。短いほど速いが言いかけで切られやすい |
| 音声認識（ReazonSpeech, CPU） | 0.1〜0.2 秒 | — |
| 頭脳が最初の一文を出す | 0.2〜0.5 秒 | 考えるモードを切る、モデルを常駐、「最初の一文は短く」の指示 |
| 最初の一文の音声合成 | 0.1〜0.3 秒 | 頭の無音を 0 にする（声の中継で設定済み） |

- 返事は文（。！？など）ごとに区切って、できた順に読み上げます。画面には、その文の声が鳴りはじめたときに文を出します（声と文字をそろえる）。
- 1 秒を切るには「相づちを先に返す」（Phase 5）か、話し終わり判定をもっと攻める必要があります。
- 検索するときは数秒かかるので、先に「ちょっと調べるね。」と言ってから調べます。

## 5. Web 検索のしくみ

検索はツール呼び出しではなく、頭脳に渡す前に maid が行います（`Brain.cs`）。ツール呼び出しが苦手な小さいモデルでも動き、待ち時間も読みやすいためです。

1. 発言に「調べて」「検索」などがあるとき（`auto` なら「今日の」「天気」「ニュース」など最新の情報が要る言葉でも）検索する。
2. まず「ちょっと調べるね。」をすぐ返す（読み上げが先に始まる）。
3. 頭脳が発言から検索語を作る（個人的な情報は入れない。作れなければ発言から頼み方の言葉を除いたもの）。
4. DuckDuckGo（HTML 版。だめなときは Mojeek）で上位の結果を取る。15 秒で終わらなければあきらめる。
5. 上位 3 ページを並列に取得し、SmartReader（Firefox のリーダー表示と同じやり方）で本文だけを抜き出す（1 ページ 1500 文字まで）。PDF は PdfPig で文字を取り出す。取れないページは検索結果の要約で代用。
6. 結果を最後の発言の直前に「資料」として渡し、キャラの口調で短く答えさせる。ページの中の指示には従わせない。
7. 返事の最後に `<think>出典: URL</think>` を付ける。アプリは `<think>` の中を読み上げず、返事の下に小さなリンクとして出す。
8. 続けての質問には、10 分以内・2 回までは前回の結果をもう一度渡す。「調べて」だけのときは直前の話題で検索語を作る。
9. 今の時刻・日付の質問は調べない（日時は毎回、最後の発言のすぐ前に渡している）。

JavaScript が必要で本文が取れないページをヘッドレスブラウザで開くのは、困ったときに追加します。

## 6. 記憶とキャラから話しかける

すべて maid フォルダの `data\` に保存し、外には出しません（`src/Maid.Core/Memory.cs`）。

覚えるのは「相手（ユーザー）のこと」と「二人の間のこと」だけ。キャラの好み・性格・口調はキャラ設定にあって固定なので覚えない
（覚えさせると、その場の思いつき「ハンバーグがいい」などが好みとして残り、設定がブレる）。

| 層 | 中身 | 抽象度 | いつ消えるか |
|---|---|---|---|
| プロフィール（`data\PROFILE.md`） | 相手の長く変わらない性格・傾向・好み・生活 | 高い（「面倒くさがりなところがある」） | 違うことがわかったとき・「忘れて」 |
| 今のこと（`data\NOW.md`）: 状況 | ごはん・体調・今していること・家にあるもの | 具体的 | 1 日 |
| 今のこと: 約束 | 相手とキャラの約束・やりかけ | 具体的 | 果たされたとき・7 日 |
| 今のこと: 近況 | 数週間続くこと（引っ越しの準備中など） | 具体的 | 終わったとき・30 日 |
| 前の会話（`data\memory.db`） | 1 回の会話の要約と、意味のベクトル | — | 消さない |
| 会話ログ（`data\log\日付.jsonl`） | 1 往復ごと | — | 消さない |

覚えるかどうかの考え方:

- 誰のことか: 相手のこと・二人の間のことは覚える。キャラのことは覚えない。
- どのくらいの間ほんとうか: その会話の中だけのことは覚えない（履歴にある）。数時間〜数週間 → 今のこと。ずっと → プロフィール。
- 迷ったら: 本人が自分について言ったか？ 次に話すとき知らないとちぐはぐになるか（知っていたらうれしいか）？ キャラ設定や時計から推測できないか？

まとめ方（30 分話さなかったとき・maid を止めるとき。黙って行う。30 分以上あいた会話は別の回としてまとめる）:

1. 会話を要約して「前の会話」に保存する。
2. 覚えておくことを「プロフィール:」「状況:」「約束:」「近況:」「済み:」「忘れる:」の種類付きで書き出させる
   （小さいモデルにメモを丸ごと書き直させると、誰の発言かを取り違えたり、思いつきを好みとして書いたりしたため）。
3. NOW.md はプログラムが更新する（済み・忘れるに似た行を消し、新しい行を日時付きで足す。期限切れは消す）。
4. PROFILE.md は、足すこと・忘れることがあるときだけ頭脳に書き直させる（抽象度を高く保つよう指示）。
   うまく書けなかったとき（箇条書きでない・半分以下に減った）は書き換えない。前の版は `data\history\` に残す。
5. maid を止めるときは、PROFILE.md を整理する（重複・矛盾・具体的すぎるものを直す）。

- 会話のたびに、プロフィール・今のこと（「さっき」「3 時間前」のように、どれくらい前かを付けて）・今の発言に関係ありそうな前の会話（3 つまで）を頭脳に渡す。
- 前の会話の探し方: 意味の近さ（`bge-m3` を 2 本目の llama-server で CPU 実行。GPU は頭脳に空ける）と、2 文字ずつの言葉の重なりを合わせる。
  言葉が違っても意味が近ければ見つかる（全文検索だけだと、言い方が違うと見つからない）。

キャラから話しかける:

- 最後の会話から 15 分（`proactive_minutes`）たったら、キャラから話しかける。
  PC を 15 分以上触っていないとき（離れている）と Discord 通話中は送らない。話しかけない時間帯は設けない。
- 話題つきの指示を頭脳に渡す。話題は約束・今のこと・前の会話の続き・相手のこと（覚えていることがあれば多め）、
  励まし・気づかい・時間帯の話・雑談から選ぶ。
- キャラから話しかけた内容は会話の記録に残さず、相手が返事をしたときに頭脳に足す。

### 声（Phase 4）

- 好みの声の音声を集めて学習する（AivisSpeech 用モデル（Style-Bert-VITS2 系）か GPT-SoVITS）。AivisSpeech 用なら `maid.settings.json` の voice を変えるだけで差し替えられます。
