# maid 仕様書

PC 上でいつでも音声で話せる、好みの声と性格のキャラクター兼調べものエージェント。完全に個人用。

## 1. 環境

| 項目 | 内容 |
|---|---|
| CPU | Core i7-11700F（8 コア 16 スレッド） |
| GPU | RTX 3060 Ti（**VRAM 8GB**） |
| RAM | 16GB |
| OS | Windows |
| 音声出力 | ヘッドホン（エコー対策は不要） |
| マイク | 本体の物理ミュートボタンを使う |

VRAM 8GB がいちばんの制約です。**GPU は頭脳（LLM）専用**にして、音声認識と音声合成は CPU で動かします。

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| 基盤 | Open-LLM-VTuber v1.2.1（本体は改造せず、前後に中継を挟む。設定で変えられない部分だけ起動時に直す） |
| PC を汚さない | インストーラー・winget・PATH の変更なし。全部 `runtime\` に入れる |
| 入力 | 音声とチャット |
| 待受 | 常時待受・ウェイクワードなし。ミュートは物理ボタン |
| Discord | 通話中は自動で声に反応しない（チャットは使える） |
| 割り込み | キャラが話している途中で話しかけたら止まる |
| 応答速度 | 速いほど良い。目標は話し終わってから 1 秒未満 |
| 頭脳 | ローカル LLM（Ollama）。Gemma 4 E4B（`hf.co/unsloth/gemma-4-E4B-it-GGUF:Q4_K_M`） |
| 耳 | ReazonSpeech（日本語専用、sherpa-onnx, CPU） |
| 声 | AivisSpeech（コハク/あまあま）。将来は好きな声に近い声を学習したモデル |
| 検索 | 閲覧と検索だけ（ログイン・購入・フォーム送信はしない）。ブラウザは使わない |
| 回答の出し方 | 調べた結果は声で短く答え、チャットに出典 URL を付ける |
| 外に出してよいもの | **検索語と閲覧したページだけ** |
| 記憶 | 自分の PC に保存。相手のプロフィール（抽象的）と今のこと（具体的・期限付き）と前の会話の要約。キャラの性格は固定で、育てない |
| 話しかける | 会話が 15 分無く、PC を使っているときにキャラから話しかける |
| 見た目 | VRM の 3D モデル（Open-LLM-VTuber の画面に重ねて表示）。表情は今後 |
| 画面 | Open-LLM-VTuber の Web 画面を Edge のアプリ風ウィンドウで開く |

## 3. 全体構成

```
マイク ─▶ 画面（Edge）─▶ Discord ゲート ─▶ Open-LLM-VTuber ─┬─▶ 音声認識（ReazonSpeech, CPU）
                                                            ├─▶ 頭脳の中継 ─┬▶ Ollama（GPU）
                                                            │               └▶ Web 検索 ── 外に出る: 検索語・ページの取得
                                                            └─▶ 声の中継 ─▶ AivisSpeech ─▶ ヘッドホン
```

| 部品 | ファイル | 役目 |
|---|---|---|
| 3D 表示 | `frontend/maid-vrm.js` | 画面に VRM を重ねて描く（呼吸・まばたき・視線・口の動き）。Live2D は透明にして残す（声の再生が Live2D 経由のため） |
| Discord ゲート | `services/discord_gate.py` | Discord がマイクを使っている間（＝通話中）は、マイク音声とキャラからの自発発話の合図を本体に渡さない |
| 頭脳の中継 | `services/llm_proxy.py` | 考えるモードを切る・モデルのすり替え・返事の長さの上限と繰り返しの打ち切り・今の日時を渡す・Web 検索 |
| 記憶 | `services/memory.py` | 会話ログ・前の会話の要約・メモ。頭脳の中継の中で動く |
| Web 検索 | `services/web_search.py` | DuckDuckGo で検索し、上位ページの本文を抜き出す |
| 声の中継 | `services/tts_bridge.py` | AivisSpeech を OpenAI 互換の TTS として見せる |
| 本体への修正 | `scripts/olv_patch.py` | 画面のマイク設定の不具合を直す・conf.yaml を maid の形にそろえる |

## 4. 応答速度

話し終わってから声が出るまでの内訳（概算）:

| 段階 | 目安 | 調整方法 |
|---|---|---|
| 話し終わり判定 | 約 0.9 秒 | `maid.settings.json` の `silence_ms`。短いほど速いが言いかけで切られやすい |
| 音声認識（ReazonSpeech, CPU） | 0.1〜0.2 秒 | — |
| 頭脳が最初の一言（読点まで）を出す | 0.2〜0.4 秒 | 考えるモードを切る、モデルを常駐、「最初の一文は短く」の指示 |
| 最初の一言の音声合成 | 0.1〜0.3 秒 | 頭の無音を 0 にする（声の中継で設定済み） |

- Open-LLM-VTuber の「最初の読点で読み上げを始める」（`faster_first_response`）を有効にしています。
- 1 秒を切るには「相づちを先に返す」（Phase 5）か、話し終わり判定をもっと攻める必要があります。
- 検索するときは数秒かかるので、先に「ちょっと調べるね。」と言ってから調べます。

## 5. Web 検索のしくみ

検索は Open-LLM-VTuber のツール呼び出し（MCP）ではなく、頭脳の中継の中で行います。ツール呼び出しが苦手な小さいモデルでも動き、待ち時間も読みやすいためです。

1. 発言に「調べて」「検索」などがあるとき（`auto` なら「今日の」「天気」「ニュース」など最新の情報が要る言葉でも）検索する。
2. まず「ちょっと調べるね。」をすぐ返す（読み上げが先に始まる）。
3. 頭脳が発言から検索語を作る（個人的な情報は入れない。作れなければ発言から頼み方の言葉を除いたもの）。
4. DuckDuckGo（`ddgs` パッケージ。だめなときは ddgs が選ぶほかのエンジン）で上位の結果を取る。
5. 上位 3 ページを並列に取得し、`trafilatura` で本文だけを抜き出す（1 ページ 1500 文字まで）。PDF は `pypdf` で文字を取り出す。取れないページは検索結果の要約で代用。
6. 結果を最後の発言の直前に「資料」として渡し、キャラの口調で短く答えさせる。ページの中の指示には従わせない。
7. 返事の最後に `<think>出典: URL</think>` を付ける。Open-LLM-VTuber は `<think>` の中を画面に「( … )」と出すだけで読み上げない
   （`[ ]` で囲むと、URL の「.」で文が切られて括弧が分かれ、読み上げられてしまった）。
8. 続けての質問には、10 分以内・2 回までは前回の結果をもう一度渡す。「調べて」だけのときは直前の話題で検索語を作る。
9. 今の時刻・日付の質問は調べない（日時は毎回、最後の発言のすぐ前に渡している）。

JavaScript が必要で本文が取れないページをヘッドレスブラウザで開くのは、困ったときに追加します。

## 6. 記憶とキャラから話しかける

すべて maid フォルダの `data\` に保存し、外には出しません（`services/memory.py`。頭脳の中継の中で動く）。

覚えるのは「相手（ユーザー）のこと」と「二人の間のこと」だけ。キャラの好み・性格・口調はキャラ設定にあって固定なので覚えない
（覚えさせると、その場の思いつき「ハンバーグがいい」などが好みとして残り、設定がブレる）。

| 層 | 中身 | 抽象度 | いつ消えるか |
|---|---|---|---|
| プロフィール（`data\PROFILE.md`） | 相手の長く変わらない性格・傾向・好み・生活 | 高い（「面倒くさがりなところがある」） | 違うことがわかったとき・「忘れて」 |
| 今のこと（`data\NOW.md`）: 状況 | ごはん・体調・今していること・家にあるもの | 具体的 | 1 日 |
| 今のこと: 約束 | 相手とキャラの約束・やりかけ | 具体的 | 果たされたとき・7 日 |
| 今のこと: 近況 | 数週間続くこと（引っ越しの準備中など） | 具体的 | 終わったとき・30 日 |
| 前の会話（`data\memory.db`） | 1 回の会話の要約と、意味のベクトル | — | 消さない |
| 会話ログ（`data\log\日付.jsonl`） | 1 往復ごと | — | 消さない |

覚えるかどうかの考え方:

- 誰のことか: 相手のこと・二人の間のことは覚える。キャラのことは覚えない。
- どのくらいの間ほんとうか: その会話の中だけのことは覚えない（履歴にある）。数時間〜数週間 → 今のこと。ずっと → プロフィール。
- 迷ったら: 本人が自分について言ったか？ 次に話すとき知らないとちぐはぐになるか（知っていたらうれしいか）？ キャラ設定や時計から推測できないか？

まとめ方（30 分話さなかったとき・maid を止めるとき。黙って行う。30 分以上あいた会話は別の回としてまとめる）:

1. 会話を要約して「前の会話」に保存する。
2. 覚えておくことを「プロフィール:」「状況:」「約束:」「近況:」「済み:」「忘れる:」の種類付きで書き出させる
   （小さいモデルにメモを丸ごと書き直させると、誰の発言かを取り違えたり、思いつきを好みとして書いたりしたため）。
3. NOW.md はプログラムが更新する（済み・忘れるに似た行を消し、新しい行を日時付きで足す。期限切れは消す）。
4. PROFILE.md は、足すこと・忘れることがあるときだけ頭脳に書き直させる（抽象度を高く保つよう指示）。
   うまく書けなかったとき（箇条書きでない・半分以下に減った）は書き換えない。前の版は `data\history\` に残す。
5. maid を止めるときは、PROFILE.md を整理する（重複・矛盾・具体的すぎるものを直す）。

- 会話のたびに、プロフィール・今のこと（「さっき」「3 時間前」のように、どれくらい前かを付けて）・今の発言に関係ありそうな前の会話（3 つまで）を頭脳に渡す。
- 前の会話の探し方: 意味の近さ（`bge-m3` を Ollama で CPU 実行。GPU は頭脳に空ける）と、2 文字ずつの言葉の重なりを合わせる。
  言葉が違っても意味が近ければ見つかる（全文検索だけだと、言い方が違うと見つからない）。

キャラから話しかける:

- Discord ゲートが、最後の会話から 15 分（`proactive_minutes`）たったら本体に「話しかけて」の合図を送る。
  PC を 15 分以上触っていないとき（離れている）と Discord 通話中は送らない。話しかけない時間帯は設けない。
- 頭脳の中継が、本体の英語の指示を話題つきの指示に置き換える。話題は約束・今のこと・前の会話の続き・相手のこと（覚えていることがあれば多め）、
  励まし・気づかい・時間帯の話・雑談から選ぶ。
- Open-LLM-VTuber はキャラから話しかけた内容を履歴に残さないので、相手が返事をしたときに頭脳の中継が足す。

### 将来: Windows ネイティブアプリ

いずれ Open-LLM-VTuber への依存をなくし、自作の Windows アプリにしたい（コードの流用は可）。今のうちから、maid 側の部品は
Open-LLM-VTuber に依存しない形にしておく:

- そのまま使える: 頭脳の中継（`llm_proxy.py`・`web_search.py`・`memory.py`。OpenAI 互換の API なら何でも相手にできる）、
  声の中継（`tts_bridge.py`）、3D 表示（`frontend/maid-vrm.js`。three-vrm なのでアプリの中の WebView でも動く）
- 作り直しが要る: マイクと話し終わりの判定（今は画面の VAD）、音声認識の呼び出し、文ごとに区切って読み上げる流れ、割り込み、
  会話の履歴、Discord ゲート（アプリの中に入れれば中継は不要）
- 画面は WebView2（Windows に標準で入っている）に three-vrm を載せるのがいちばん近道

### 声（Phase 4）

- 好みの声の音声を集めて学習する（AivisSpeech 用モデル（Style-Bert-VITS2 系）か GPT-SoVITS）。AivisSpeech 用なら `maid.settings.json` の voice を変えるだけで差し替えられます。
- 実在の人の声を学習するときは、個人で楽しむ範囲にとどめ、生成した音声を公開・配布しません。
